**Symptom:** The patient profile "Notes" tab applies no role-based access control on the frontend. Any user who can open a patient profile sees the tab, and the notes UI is rendered with read and write both hardcoded to true.

**Evidence to verify before filing:**
- `src/components/Patient/PatientDetailsTab/PatientNotes.tsx` — renders `<NoteManager canAccess={true} canWrite={true} ... hideEncounterNotes={true} />`. Both flags are literal `true`, with no permission lookup.
- `src/components/Patient/PatientDetailsTab/index.tsx` — the tab-visibility switch has no `case "notes":`, so it falls to the `default` branch, `visible` stays `undefined`, and the later `.filter(tab => tab.visible ?? true)` always keeps the tab.
- Contrast with the encounter side, `src/pages/Encounters/tabs/notes.tsx`, which correctly passes `canReadSelectedEncounter` and `canWriteSelectedEncounter` from `src/pages/Encounters/utils/EncounterProvider.tsx`.

**Expected behavior:** The patient Notes tab should be gated by the same permissions the backend enforces for patient-scoped note threads:
- read → `can_view_clinical_data` ("Can view clinical data about patients")
- write → `can_write_patient` ("Can Update a Patient's data")

Backend reference (do not change the backend): `care/emr/api/viewsets/notes.py` — `NoteThreadViewSet.get_queryset` requires `can_view_clinical_data` on the patient, and `authorize_create` / `authorize_update` require `can_write_patient_obj` when the thread has no encounter.

**Note this in the issue:** the backend does enforce these permissions, so this is not a data-exposure hole at the API layer. The impact is a misleading UI — a user without the permission still sees the Notes tab and a working composer, and only discovers the refusal after the request fails.

2. In `PatientNotes.tsx`, derive `canAccess` and `canWrite` from the patient permissions hook the rest of the patient tabs already use, instead of the hardcoded `true` values. Investigate and name the exact hook/context the sibling patient tabs use, so the issue gives an actionable pointer.

## Scope
How a user selects a discussion, reads the messages in it, and posts a new message. Applies to both the encounter Notes tab and the patient profile Notes tab; the screen is identical in both.

## Verified facts (use ONLY these)

**Before you start**
- A discussion exists in the list you look at. If none exists, start one first.
- To post in an encounter discussion, the encounter must not be complete.

**Steps**
1. Go to the **Notes** tab of the encounter or of the patient profile. In an encounter, press `g` then `n` to go to the Notes tab.
2. Select a discussion in the list on the left. On a small screen, open the list first and then select the discussion. Care opens the most recent discussion for you if you select none.
   - Before you select a discussion, the screen shows "Welcome to Discussions" and "Start a new discussion or select an existing thread to begin messaging". The heading area shows "Select or create a thread to start messaging".
3. Read the messages. The newest message is at the bottom. Each message shows the author's picture and name, and how long ago the message was sent. Point at the time to see the full date and time. Select the author's name or picture to open that user's profile.
4. Care loads older messages while you scroll up, 20 messages at a time.
5. Type in the box with the placeholder "Type your message...". The box gets taller as you type more lines.
6. Select the send button. On a computer, you can also press `Shift` and `Enter` together to send. On a touch screen, use the send button.
7. Care adds your message at the bottom of the discussion and moves the view to it.

**What a message can hold**
- Text with Markdown formatting. Care shows the formatted result.
- Care does not support file attachments.
- Care does not support mentions of other users.
- The heading of the discussion shows how many people took part and how many messages the discussion holds.

**Rules and limits**
- You cannot delete a message.
- Care shows no way to change a message after you send it.
- You cannot post a message in an encounter that is complete.

**Permissions** (backend-enforced, human-readable names)
- To read messages in an encounter discussion: **"Can Read encounter related clinical data"** — Doctor, Nurse, Administrator, Facility Admin.
- To post a message in an encounter discussion: **"Update Encounter related clinical data"** — Doctor, Nurse, Administrator, Facility Admin.
- To read messages in a patient discussion: **"Can view clinical data about patients"** — Staff, Doctor, Nurse, Administrator, Facility Admin.
- To post a message in a patient discussion: **"Can Update a Patient's data"** — Staff, Doctor, Nurse, Administrator, Facility Admin.

**Configuration:** no deployment setting changes this flow.

**Known limitation worth a short note to the reader:** if the message cannot be sent, Care gives no message on screen. Mention this once, plainly, as a caution — do not speculate about causes.

## Verified facts (use ONLY these)

**Where you start from**
- **Encounter context:** open the encounter and go to the **Notes** tab. Keyboard shortcut: press `g` then `n` to go to the Notes tab. A discussion you start here belongs to that encounter.
- **Patient profile context:** open the patient profile and go to the **Notes** tab. A discussion you start here belongs to the patient and to no encounter.
- The two lists never overlap. A discussion you start in an encounter does not appear on the patient profile, and the reverse is also true.

**Steps**
1. Go to the Notes tab in either context.
2. Select **New** above the discussion list. On a small screen, use the **New Thread** button. If no discussion exists yet, you can also select **Start New Discussion** in the middle of the screen.
3. Care opens the **Start New Discussion** dialog. An information icon next to the title explains: "Create a new discussion thread to organize your conversation topics."
4. The dialog shows "Choose a template or enter a custom title". Select one of these suggested titles, or type your own in the box with the placeholder "Enter discussion title...":

   - Medication Notes
   - Care Coordination
   - General Notes
   - Patient History
   - Referral Notes
   - Lab Results Discussion

5. Select **Create**. The button stays unavailable while the title box is empty.
6. Care shows "Thread created successfully" and opens the new discussion. You can now post the first message.
- To stop without creating a discussion, select **Cancel**.

**Rules and limits**
- A title can hold a maximum of 255 characters.
- Two discussions in the same list cannot share a title. If the title is already in use, Care shows "Thread with this title already exists" and does not create the discussion.
- If the discussion cannot be created, Care shows "Failed to create thread".
- You cannot start a discussion in an encounter that is complete.
- You cannot delete a discussion after you create it.
- Care shows no way to rename a discussion.

**Permissions** (backend-enforced, human-readable names)
- To start a discussion inside an encounter: **"Update Encounter related clinical data"** — held by Doctor, Nurse, Administrator, and Facility Admin.

This is an **issue-filing task only**. Investigate, confirm the facts, and file a well-written issue. The user will convert it into a JIRA ticket. Report the issue URL back.

**Symptom:** The patient profile "Notes" tab applies no role-based access control on the frontend. Any user who can open a patient profile sees the tab, and the notes UI is rendered with read and write both hardcoded to true.

**Evidence to verify before filing:**
- `src/components/Patient/PatientDetailsTab/PatientNotes.tsx` — renders `<NoteManager canAccess={true} canWrite={true} ... hideEncounterNotes={true} />`. Both flags are literal `true`, with no permission lookup.
- `src/components/Patient/PatientDetailsTab/index.tsx` — the tab-visibility switch has no `case "notes":`, so it falls to the `default` branch, `visible` stays `undefined`, and the later `.filter(tab => tab.visible ?? true)` always keeps the tab.
- Contrast with the encounter side, `src/pages/Encounters/tabs/notes.tsx`, which correctly passes `canReadSelectedEncounter` and `canWriteSelectedEncounter` from `src/pages/Encounters/utils/EncounterProvider.tsx`.

**Expected behavior:** The patient Notes tab should be gated by the same permissions the backend enforces for patient-scoped note threads:
- read → `can_view_clinical_data` ("Can view clinical data about patients")
- write → `can_write_patient` ("Can Update a Patient's data")

Backend reference (do not change the backend): `care/emr/api/viewsets/notes.py` — `NoteThreadViewSet.get_queryset` requires `can_view_clinical_data` on the patient, and `authorize_create` / `authorize_update` require `can_write_patient_obj` when the thread has no encounter.

**Note this in the issue:** the backend does enforce these permissions, so this is not a data-exposure hole at the API layer. The impact is a misleading UI — a user without the permission still sees the Notes tab and a working composer, and only discovers the refusal after the request fails.

**Proposed fix to describe in the issue:**
1. In `PatientDetailsTab/index.tsx`, add a `case "notes":` to the visibility switch that sets `visible` from the patient permission for viewing clinical data.
2. In `PatientNotes.tsx`, derive `canAccess` and `canWrite` from the patient permissions hook the rest of the patient tabs already use, instead of the hardcoded `true` values. Investigate and name the exact hook/context the sibling patient tabs use, so the issue gives an actionable pointer.
3. Keep the encounter path unchanged.

Include in the issue: a clear title, the reproduction path (open a patient profile as a user without patient clinical-data permission → the Notes tab is present and writable-looking), the affected file paths with line references, the expected behavior, and the proposed fix. ## Scope
How a user selects a discussion, reads the messages in it, and posts a new message. Applies to both the encounter Notes tab and the patient profile Notes tab; the screen is identical in both.

## Verified facts (use ONLY these)

**Before you start**
- A discussion exists in the list you look at. If none exists, start one first.
- To post in an encounter discussion, the encounter must not be complete.

**Steps**
1. Go to the **Notes** tab of the encounter or of the patient profile. In an encounter, press `g` then `n` to go to the Notes tab.
2. Select a discussion in the list on the left. On a small screen, open the list first and then select the discussion. Care opens the most recent discussion for you if you select none.
   - Before you select a discussion, the screen shows "Welcome to Discussions" and "Start a new discussion or select an existing thread to begin messaging". The heading area shows "Select or create a thread to start messaging".
3. Read the messages. The newest message is at the bottom. Each message shows the author's picture and name, and how long ago the message was sent. Point at the time to see the full date and time. Select the author's name or picture to open that user's profile.
4. Care loads older messages while you scroll up, 20 messages at a time.
5. Type in the box with the placeholder "Type your message...". The box gets taller as you type more lines.
6. Select the send button. On a computer, you can also press `Shift` and `Enter` together to send. On a touch screen, use the send button.
7. Care adds your message at the bottom of the discussion and moves the view to it.

**What a message can hold**
- Text with Markdown formatting. Care shows the formatted result.
- Care does not support file attachments.
- Care does not support mentions of other users.
- The heading of the discussion shows how many people took part and how many messages the discussion holds.

**Rules and limits**
- You cannot delete a message.
- Care shows no way to change a message after you send it.
- You cannot post a message in an encounter that is complete.

**Permissions** (backend-enforced, human-readable names)
- To read messages in an encounter discussion: **"Can Read encounter related clinical data"** — Doctor, Nurse, Administrator, Facility Admin.
- To post a message in an encounter discussion: **"Update Encounter related clinical data"** — Doctor, Nurse, Administrator, Facility Admin.
- To read messages in a patient discussion: **"Can view clinical data about patients"** — Staff, Doctor, Nurse, Administrator, Facility Admin.
- To post a message in a patient discussion: **"Can Update a Patient's data"** — Staff, Doctor, Nurse, Administrator, Facility Admin.

**Configuration:** no deployment setting changes this flow.

**Known limitation worth a short note to the reader:** if the message cannot be sent, Care gives no message on screen. Mention this once, plainly, as a caution — do not speculate about causes.
